# よるの水族館 2.6 — スマートフォン向けブラウザ試作

ご提供の正式カタログ100項目（環境10・基本34・進化56）を使った、静かな探索・収集・育成ゲームです。ボクセル調の仲間を水槽で眺めながら、餌・成長・繁殖を楽しめます。

## すぐに遊ぶ

デモでは図鑑100項目と4展示室を公開。未獲得の種類は「見本」として表示され、図鑑の詳細から水槽で見るか、「この見本をお迎え（デモ）」で実際の仲間として追加できます。表示だけでは本来の獲得・発見記録を変更しません。見本は餌・繁殖・共生の対象外です。設定でデモ全公開をオフにもできます。

プレビューでは端末とワークスペースに自動保存しますが、ワークスペースの消失に備え、「設定」からJSONも書き出して保管してください。保存と旧データの扱いは後述と `docs/DEMO_AND_SAVE_2_6.md` を参照。

1. `yoru-no-suizokukan.html` をWebGL対応ブラウザで開き、「はじめる」を押します。画像・3Dコード込みのHTML単体で、通信がなくても遊べます。
2. 「はじめての探索へ」→「近海」。初回はクマノミを必ず発見。デモ設定では30秒待つか「デモ用：待ち時間をスキップ」を押します。
3. 水槽の魚をタップしてなでる／長押しして詳しく見る。水槽の下の一覧からも個体詳細を開けます。
4. **餌を選んで「えさをあげる」**。今開いている展示室・水質の水槽にだけ餌が落ち、対応する仲間が向かいます。複数の食性の仲間がいるときは「おまかせ」で、それぞれに対応した餌を一度に配れます。個体詳細では好きな餌とゲーム内で食べない餌を確認できます。
5. 水槽右下の **＋／−または2本指のピンチ**で拡大。「指で動かす」はドラッグ移動、「魚を追う」は特定の個体を追跡します。倍率表示を押すと位置・追跡もリセットします。
6. ライトのボタンを**1回タップ**するごとに月→暖色→青へ切り替わります。選択ダイアログは不要です。
7. 同じ種類の♂と♀が同じ展示室・水質で育成度A以上になり、条件を満たすと一定確率で赤ちゃんが生まれます。個体詳細から、最初のお相手は無料で迎えられます。水槽の「ふたりの、小さな物語」に条件、未成立の理由、次回判定や直前の結果が表示されます。
8. 海水／淡水／汽水タブで展示を切り替えます。環境種は水底に置かれ、詳細から展示／収納できます。動物が12体を超えるとページ送りできます。
9. 最初の案内を終えると、館の「今夜のおすすめ」に、今できる進化・空腹の仲間・次の館長賞のいずれかを表示します。**任意の案内**で、期限や報酬はありません。空腹の案内を押すと、対象の展示室・水質を開きます。
10. 図鑑は種類名・自分で付けた個体名・番号（全角数字も可）で検索でき、「出会った」「未発見」「進化できる」と展示カテゴリを組み合わせられます。通常表示では未発見の**名前**では検索できず、番号では探せます。デモ全公開中は未獲得の名前も検索できます。「進化できる」は、未発見の姿を発見できる元の種類を表示します。複数個体がいる種類では一覧から個体を選び、詳細から一覧に戻れます。検索・絞り込みは一時的で再読込すると初期化されます。
11. 個体詳細の「進化のヒント」では、条件ごとの達成／未達成と現在値を表示します。未発見の姿の名前は伏せられ、条件がそろったら「新しい姿を発見」から迎えられます。**親は残り**、新しい個体が水槽に加わります。未達のライト条件がある場合、詳細画面内からもライトを1回ずつ切り替えられます。
12. 個体詳細で、同じ個体に固定された「性格」と種類に応じたしぐさを確認できます。見た目の違いだけで、育成や繁殖の有利・不利はありません。好感度が上がるのは1日10回までですが、それ以降もなでる演出は楽しめます。
13. 水槽・図鑑の「ふたりのワンシーン」で、既存のゲーム内共生4組の記録を見られます。同じ展示室・水質に2種を展示中なら、場面を再生できます。水槽を見ている時にも自然に起こります。実際の生態・混泳の再現ではありません。
14. 水槽の「かざり・配置」→「この水槽の配置を変える」。水草・岩・砂を上から見た図で動かし、45度ずつ回転できます。移動はドラッグか矢印、対象選択は図か一覧から。3つの見本も使えます。配置は展示室・水質ごと、飾りの数は従来通り全展示室共通です。
15. 3時間以上離れてから戻ると、復帰時に確定した探索・誕生・成長などを「おかえりの、きろく」に最大3件表示します。タップで水槽などに移動でき、閉じても進行には影響しません。何も起きていないときは挨拶だけです。
16. 水槽の動物は**小型・中型・大型**で大きさが変わります。画面下の「表示中」に各区分の数を表示。図鑑では発見済みの仲間（デモ全公開中は見本も）に区分が付き、「大きさでさがす」から絞り込めます。サンゴや海草など環境10項目はサイズ分類の対象外です。サムネイルは見やすい大きさで表示されるため、大きさの比較は水槽で確認してください。

### すぐに繁殖を試す

デモ設定のまま、仲間の詳細で「お相手を迎える」→その2体それぞれの詳細で「デモ：育成度をAまで進める」→水槽の「ふたりの、小さな物語」を開きます。「デモ：1回判定」は**待ち時間だけをスキップ**し、1回30％の判定を行います。必ず生まれるボタンではありません。

デモでは探索30／45／60秒、探索券は5秒ごとに1枚回復、繁殖判定は1分。設定でデモをオフにすると探索3／4／6時間、券の回復3時間、繁殖判定24時間です。すでに始まった探索・繁殖タイマーの時刻や間隔は、設定を切り替えても変わりません。

## 餌・育成・繁殖の考え方

- 餌はプランクトン、小さな虫、小魚・貝、水草・海藻、専用食の5グループ。手動で好きな餌を選ぶと育成度＋12、その他の対応する餌は＋8。**おまかせ**は各個体に合う餌を一度に配り、育成度＋8です。いずれも共生等による追加があります。手動の非対応個体は変化せず、誰も食べられないときは回数を消費しません。おまかせも通常の給餌1回分を使います。
- 「おなか」は適合する餌で＋35、時間経過で1時間につき1減ります（2.3までは2）。20以上のときは放置でも少しずつ成長し、20未満では成長・繁殖を休みますが、**病気や死亡はありません**。旧セーブにも新しい減少率を適用するため、更新時のおなかや未処理の留守中成長の計算結果が以前より高くなる場合があります。
- ペアは同種・同展示室・同水質、A以上、♂と♀、判定時のおなか20以上が条件です。親子や兄弟姉妹は組みません。同種は全展示室合計で最大6匹。留守中の繁殖判定は最大7回分です。
- 個体に任意の名前をつけられ、食事・成長・誕生の観察ノートや、子の親を確認できます。詳細画面は操作後もスクロール位置を保ち、閉じるボタンはスクロール中も使えます。キーボードではTabで画面内を移動し、Escで閉じられます。
- 詳細仕様、90項目の餌とサイズ設定、参考資料、簡略化の範囲は `CARE_AND_BREEDING.md`。5つの追加企画の採否は `PLANNING_DECISIONS.md`、今回の改善と限界は `CHANGELOG.md` を参照してください。

## 100項目のデザインと科学的な扱い

- `DESIGN_GALLERY.html` は、未発見の仲間を含む全100種類の3Dサムネイルの一覧です。名前・展示・区分で検索できます。単独でオフライン表示できます。
- 2.6プロジェクトには実行・ビルドに必要な背景WebPを収録しています。元の背景PNGとご提供の参考PNGは大きいため2.6 ZIPには含めていません。必要な場合は元の添付画像、または以前の `yoru-web-2.4-project.zip` の `assets/night-gallery.png`・`docs/reference-design.png` を使えます。
- 番号、名称、レア度、展示カテゴリ、56の進化条件は添付原稿を反映。造形と生息情報の判断・55件の参考文献は `SPECIES_REVIEW.md` に記載しています。
- 魚以外の生きもの、未確定の名前、創作形態、別種・同物異名を区別しています。魚、海棲哺乳類、カメ、エイ、エビ、軟体動物、環境種で異なるボクセル形状を使用しますが、共通体型も再利用しています。
- 餌・性別・繁殖・進化・共生・混泳は**ゲーム用の簡略化**です。実際の飼育・適正水質・食餌・繁殖方法を示すものではありません。ウミウシの雌雄同体、クマノミの性転換など、多様な現実のしくみは再現していません。外部専門家による監修は未実施です。
- 動物90項目は小型48・中型23・大型19に分類。クマノミは小型、マグロは中型、イルカ・ネコザメは大型というご要望に合わせた**ゲーム上の目安**です。実際にはクロマグロがネコザメより大きくなる場合もあり、分類は学術上の大きさの区分ではありません。画面は実寸比ではなく、体型・向き・個体差によって見え方が変わります。全項目は `docs/SIZE_CLASSES_2_5.md`、根拠と限界は `CARE_AND_BREEDING.md` を参照。

## 条件の解釈

- 原稿の育成度A＝40、S＝100。単一ライトの条件は**現在のライト**で判定し、#68の「青＋月」だけは同じ個体が両方のライトを順に体験した履歴で判定します。
- 草・砂の個数は共通のかざりに、同じ展示室・水質で展示中の対応環境種を加算。サンゴ・イソも原稿上の**ゲーム属性**で判定します。ホヤに「サンゴ」タグがあっても、生物学上サンゴという意味ではありません。
- 共生条件は現在成立中の組数です。発見履歴は別に残り、環境種を収納／別室へ移すと現在の成立は解除されます。
- 探索は生きもの80％・素材15％・かざり5％。生きものの抽選では未発見種の重みを1.5倍にしますが、再会もあります。探索画面には現在の確率を表示。進化種は探索対象ではありません。重複動物は同種6匹まで仲間にでき、以後は素材化。環境種と飾りは既取得なら素材化します。初回探索はクマノミを保証します。

## 保存・オフライン・旧版の移行

- ブラウザの `localStorage` に自動保存します。保存は端末・ブラウザ・URLのオリジンごとに別で、ブラウザのデータを消すと失われます。
- `npm start` のプレビューでは、これに加えてワークスペース内 `preview-data/current.json` にも自動バックアップします。同じ保存先に接続でき、新URLの端末内保存が空なら自動復元します。ワークスペースの消失、別ワークスペースへの移動、接続・書き込み障害は保証できないため、重要なデータはJSONを手元に保存してください。一般向けアカウント／クラウド同期ではありません。
- 端末とワークスペースに異なるデータがある場合はどちらも勝手に上書きせず、両方の書き出しと選択画面を表示します。ワークスペースのリビジョンが先に更新された場合も競合として停止。サーバー側の直前1件 `previous.json` は次の保存で更新され、長期保管には使えません。
- **別URLの古いブラウザ保存は直接読めません。** 2.6導入前の旧URLがまだ開いて仲間が残っていれば、旧画面の「設定 → 現在のセーブを書き出す」でJSONを保存し、新画面の「ファイルから読み込む」で移行してください。旧URL・JSON・ワークスペースにデータが残っていなければ自動復元できません。
- ダウンロードした単体HTMLや通常の静的ホスティングにはワークスペースへの自動バックアップはありません。端末内への自動保存とJSON移行を使用します。読み込みは確認後に現在の進行を置き換え、直前の状態は1回だけ戻せます。次の読み込みや初期化では復元ポイントが変わるため、移動前後の両方を先に保存してください。
- 同じオリジンの2.4／2.5のv5保存はそのまま引き継ぎます。v4は個体を維持し性別・お世話を補ってv5へ移行。v3は同名種を正式図鑑に対応付け、他の個体も旧版の仲間として保持します。v4／v3の元データは変更せず書き出せます。読み込めない保存は自動上書きせず保護します。
- JSONとワークスペースの保存には仲間の名前や進行記録が入り、暗号化されません。プレビューにアクセスできる人は保存も見られるため、URLやファイルを第三者に共有しないでください。配布ZIPに個人の `preview-data` は含めません。
- 以前のPWA版から更新するときはオンラインで開いて再読込してください。オフラインのままでは旧キャッシュが表示されることがあります。Service WorkerはバックアップAPIをキャッシュしません。
- `index.html` と `yoru-no-suizokukan.html` は同一の自己完結版。HTTPSのPWAは初回読込後にオフライン起動できます。ローカルファイルもオフライン動作します。
- 詳しい制限、見本とお迎えの違い、データを救出する手順は `docs/DEMO_AND_SAVE_2_6.md` を参照。

## 開発・テスト

Node.js 20系以降（開発時は20.20.2）で以下を実行します。2.6のソースZIPには再生成できるHTML・ギャラリー・`game.bundle.js`を含めていません。別添のHTMLはそのまま開けますが、ソースZIPを展開した場合は最初に `npm ci` と `npm run build` を実行してください。初回の依存取得はネット接続が必要です。

```sh
npm ci
npm run build       # ゲームHTML、全100種の一覧、お世話仕様書・サイズ一覧を再生成
npm test            # 正式カタログとゲームロジックのテスト
npm start           # オプションのワークスペース自動バックアップ付きプレビュー
```

別ターミナルでPlaywright Chromiumを用いてブラウザ検証を実行します。Linuxでは必要に応じて `npx playwright install-deps chromium` も実行します。

```sh
npx playwright install chromium
# テスト用の静的サーバーを別ターミナルで起動（実際のセーブと分離）
python3 -m http.server 3001 --bind 127.0.0.1
BASE_URL=http://127.0.0.1:3001/ npm run test:e2e
npm run test:backup    # 一時ディレクトリでバックアップと競合を検証
npm run balance:check  # 食事・探索バランスの簡易シミュレーション
```

旧Web 2.4／2.5からの実更新と、2.5からバックアップ経由で別オリジンへ復元する試験も、前版のZIPを展開して指定すれば再現できます（サーバーはテスト内で一時起動）。

```sh
unzip yoru-web-2.4-project.zip -d /tmp/yoru-previous
OLD_WEB_DIR=/tmp/yoru-previous/yoru-web-2.4 npm run test:upgrade
unzip yoru-web-2.5-project.zip -d /tmp/yoru-previous
OLD_WEB_DIR=/tmp/yoru-previous/yoru-web-2.5 npm run test:upgrade25
```

100種のサムネイルを再生成する場合は、上記サーバーを起動したまま `npm run thumbs` を実行し、続けて `npm run build` を実行します。ChromiumとWebGLが必要で、使用環境により見た目が少し変わる場合があります。

同梱の `docs/GAME_DESIGN_COMPLETE.md` はご提供いただいた元の設計書であり、餌・重複・育成の新仕様はこのREADMEと `CARE_AND_BREEDING.md` を優先します。

主な構成：`catalog-data.json`／`species-profiles.js`（正式カタログと生態）、`care-profiles.js`（食性・大きさの参考値）、`size-classes.js`（大きさの3分類と水槽倍率）、`species-models.js`／`models.js`（3D）、`engine.js`（ゲームロジック）、`personality.js`（個体ごとの見た目の性格）、`decor-layout.js`（水槽ごとの配置）、`progress.js`（任意のおすすめ・検索）、`demo-showcase.js`（非破壊の見本）、`save-transfer.js`（セーブ検証・復元）、`preview-backup.js`／`preview-server.mjs`（プレビュー保存と競合保護）、`aquarium-scene.js`（水槽・餌・カメラ・ワンシーン）、`main.js`／`template.html`（UI）、`docs/`（ご提供原稿・2.4仕様・2.5サイズ一覧）。

## Flutter版について

現在のFlutter試作はWeb 2.4の追加要素・バランス、2.5のサイズ分類、2.6のデモ全公開とプレビュー保存をまだ実装していません。WebとFlutterの保存領域は別で、2.4以降のセーブ移行は未検証です。移植用の仕様・注意点は `docs/LIVING_AQUARIUM_2_4.md` にまとめています。

## 製品版ではない部分

本作はブラウザ試作です。Unity／ネイティブ化、ストア配信、広告SDK、プッシュ通知、一般向けクラウド同期、運営基盤、実機での性能保証は未実装または未検証。強制広告・課金ガチャはありませんが、無料の探索・繁殖には確率があります。
