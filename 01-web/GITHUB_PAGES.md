# GitHub Pages の公開設定

この変更は**公開用の設定を用意するPR**です。作成しただけでは公開されません。Pagesの有効化、PRのマージ、実際のデプロイは別の操作です。

対象リポジトリ：`koki-ota0/night-aquarium`。標準設定での公開先は **https://koki-ota0.github.io/night-aquarium/** の予定です。デプロイ成功を確認するまでは公開済みURLとして扱わないでください。

## 公開する手順（承認後に実施）

1. GitHubのリポジトリで **Settings → Pages → Build and deployment → Source → GitHub Actions** を選びます。
2. Actionsが無効なら **Settings → Actions → General** で有効にします。使用する公式Actionsが組織・リポジトリの許可リストに含まれていることも確認します。
3. PRの差分・検証結果を確認して `main` にマージします。
4. **Actions → Web Pages** の `build` と `deploy` が成功するのを確認します。`github-pages` 環境に承認ルールを設定した場合は承認も必要です。
5. 成功したデプロイのURLを開き、タイトル・館内・水槽・保存・再読み込みを確認します。

先にマージして後からPagesを有効にした場合は、**Actions → Web Pages → Run workflow → main** から実行できます。別ブランチからの手動実行は検証・ビルドだけで、公開しません。

事前確認では `has_pages=false` を確認しています。現在のArena接続ではActions管理設定の確認APIが403で拒否されたため、管理設定は変更していません。権限エラーが出る場合はArenaのGitHub接続を再連携して対象リポジトリへのアクセスを確認するか、管理権限を持つユーザーがGitHub画面で設定してください。パスワードやトークンを会話へ貼る必要はありません。

## ワークフローの動き

`.github/workflows/pages.yml` は次を行います。

- `main` 向けPRではテストとビルドだけを実行し、公開はしません。
- `main` への関連ファイルのpush、または `main` 上の手動実行で、検証成功後にのみ公開します。
- Node.js 22 / lockfile を使い、`npm test` → `npm run build:pages` → `npm run test:pages` を実行します。ブラウザ試験用ChromiumはCIで導入します。
- 公開権限（`pages: write` / `id-token: write`）は `deploy` ジョブだけに付けます。PRのビルドには付けません。Actionsは確認した公式リリースのコミットSHAに固定しています。
- `01-web/dist/` だけをPages artifactとしてアップロードします。リポジトリ全体や `01-web/` 全体はアップロードしません。公開用ブランチや外部サービスのAPIキーは不要です。

## 公開ファイルとプライバシー

`tools/package-pages.mjs` の固定許可リストで、プレイ用HTML2つ、デザイン図鑑、Service Worker、manifest、アイコン2つ、公開済みの種・お世話資料、ライセンス表示だけをコピーします。シンボリックリンクは拒否し、必要な生成物が欠けている場合も失敗させます。

`preview-data/`、実セーブ、`.env`、認証情報、`node_modules/`、Flutter、作業用資料は公開成果物に含めません。`dist/` と生成済みHTMLはGitから引き続き除外します。許可リストを変更するときは公開対象をレビューし、テストも更新してください。

Pagesは静的配信なのでプレビューの保存APIは動きません。ゲームはブラウザ内の保存とJSON書き出し・読み込みを使い、公開サイト全員で同じセーブを共有することはありません。サーバー側バックアップや端末間の自動同期はありません。

## セーブ移行と3D表示の注意

- プレビューとPagesではオリジンが異なるため、**セーブは自動で移行しません**。旧画面の「設定 → 現在のセーブを書き出す」でJSONを手元へ保管し、新URLで「ファイルから読み込む」を使います。読み込みは現在の進行を置き換えるため、移行前後のJSONを両方保管してください。セーブJSONには個体名などが含まれ、公開リポジトリへアップロードしないでください。
- WebGL2を使えない環境での3D表示は、Pagesへ移しただけでは直りません。別タブで開くことでプレビューの埋め込み条件との切り分けはできますが、ユーザー環境の原因は引き続き未特定です。「設定 → 3D表示 → 診断を見る」で確認できます。
- 初回オンライン読み込み後のオフライン再起動には対応しますが、保存の保全を保証するものではありません。サイトデータの削除を案内したり、勝手に初期化したりしないでください。

## ローカル検証

`01-web/` で実行します。稼働中のプレビューのHTMLを書き換えたくない場合は、セーブを含めない隔離コピーで実行してください。

```sh
npm ci
npm test
npm run build:pages
npx playwright install chromium       # Linuxで不足する場合は --with-deps も使用
npm run test:pages
```

`test:pages` は一時ポートで `/night-aquarium/` 配下に成果物だけを配信し、合成データだけを使います。実プレビューのポート3000や実セーブへ接続せず、相対パス・WebGL2描画・ローカル保存／JSON書き出し・Service Workerのスコープ・オフライン再起動・非公開ファイルが404になることを検証します。テスト用ソフトウェア描画での成功は、ユーザー実機での成功の証明ではありません。

### 設定PR作成前の検証結果

- `npm test`：122 / 122成功。
- `npm run build:pages`：隔離コピーで成功。成果物は13ファイル、約5.7 MiB。
- `npm run test:pages`：Linux / Chromium 153 / ANGLE・SwiftShaderで上記の静的配信・描画・保存・オフライン検証が成功。ブラウザと不足する共有ライブラリは一時ディレクトリだけに導入しました。
- ワークフローYAMLの構文、main限定の公開条件、ジョブ権限、ActionsのSHA固定、artifactの対象ディレクトリをローカルで検証しました。

これはGitHub Actions上の実行結果や、実際のPagesへのデプロイ成功を示すものではありません。この段階ではPagesの設定変更・公開・PRのマージは行っていません。
